# Telegram Bot с поддержкой множественных LLM

Telegram-бот с поддержкой нескольких LLM провайдеров (OpenAI GPT, Yandex GPT, DeepSeek) и структурированных ответов в форматах JSON, XML и текстовом представлении.

## 🌟 Новое в этой версии

- **RAG (Retrieval Augmented Generation) ⚡ NEW!:**
  - 🔍 **Семантический поиск по документам** с использованием эмбеддингов
  - 🔗 **Кликабельные ссылки на источники** через MCP filesystem сервер
  - Локальная генерация эмбеддингов через Ollama (bge-m3)
  - Автоматическое использование контекста из документов в DeepSeek
  - Цитирование источников с указанием релевантности
  - CLI для управления индексом: `manage_index.py`
  - Поддержка markdown (.md) и текстовых (.txt) файлов
- **Поддержка нескольких LLM провайдеров:**
  - OpenAI GPT (gpt-3.5-turbo) - по умолчанию
  - Yandex GPT (yandexgpt-lite)
  - DeepSeek (deepseek-chat) с поддержкой RAG
- **Динамическое переключение между моделями** с командами `/openai`, `/yandex`, `/deepseek`
- **Персистентное хранение выбора** пользователя между сессиями
- **Автоматический fallback** на Yandex GPT при недоступности выбранного провайдера
- **Модульная архитектура** для легкого добавления новых провайдеров

## Быстрый старт

### 1. Установите зависимости

```bash
pip install -r requirements.txt
```

### 2. Настройте переменные окружения

Создайте файл `.env` на основе `.env.example`:

```env
# Обязательные параметры
TELEGRAM_TOKEN=ваш_TELEGRAM_TOKEN
YANDEX_API_KEY=ваш_yandex_api_key
YANDEX_FOLDER_ID=ваш_yandex_folder_id

# Опциональные параметры (рекомендуется минимум один)
OPENAI_API_KEY=ваш_openai_api_key
DEEPSEEK_API_KEY=ваш_deepseek_api_key
```

**Примечание:** Yandex GPT используется как fallback провайдер, поэтому его ключ обязателен. OpenAI используется по умолчанию для новых пользователей.

### 3. Запустите бота

```bash
python bot.py
```

### 4. Протестируйте в Telegram

```
# Основные команды
/start              - Начать работу с ботом
/help               - Справка по командам

# Выбор LLM модели
/openai             - Переключиться на OpenAI GPT
/yandex             - Переключиться на Yandex GPT
/deepseek           - Переключиться на DeepSeek
/model              - Показать текущую модель

# Режимы вывода
/text               - Переключить на текстовый режим (по умолчанию)
/json               - Переключить на JSON режим
/xml                - Переключить на XML режим
/status             - Показать текущий режим

# Управление сессиями
/session_info       - Информация о текущей сессии
/new_session        - Начать новую сессию (сбросить контекст)
/end_session        - Завершить текущую сессию

# Дополнительные возможности
/test_temperature   - Тестирование разных температур LLM
/memory_stats       - Статистика памяти (сообщения, факты, сессии)
/clear_memory       - Очистить историю диалога
/export_memory      - Экспортировать историю (text/json/csv)
/mcp_tools          - Показать доступные MCP инструменты
```

### Тестирование температуры LLM

**Что такое температура?**

Температура (temperature) — это параметр LLM, который контролирует степень случайности и креативности в ответах модели. Чем выше температура, тем более разнообразные и креативные ответы генерирует модель.

#### Использование команды

```
You: /test_temperature
Bot: [Тестирует с дефолтным промптом "Придумай название для стартапа по доставке еды"]

You: /test_temperature Придумай слоган для кофейни
Bot: [Тестирует с вашим промптом]
```

#### Результат тестирования

Бот отправит три ответа от модели с разными температурами:
- **Temperature = 0** (детерминированность) - стабильные, предсказуемые ответы
- **Temperature = 0.7** (сбалансированность) - универсальный режим
- **Temperature = 1.0** (креативность) - оригинальные, разнообразные ответы

Затем бот проведет автоматический анализ и предоставит:
- Сравнение схожести между ответами
- Оценку вариативности результатов
- Рекомендации по выбору температуры для вашей задачи

#### Когда использовать разные температуры

**Temperature = 0 (Детерминированность)**
- Точные ответы на фактические вопросы
- Классификация и категоризация
- Извлечение данных из текста
- Переводы
- Технические инструкции

**Temperature = 0.7 (Сбалансированность)**
- Диалоги и общение
- Ответы на общие вопросы
- Объяснения и обучение
- Повседневные задачи
- Рекомендуется по умолчанию

**Temperature = 1.0 (Креативность)**
- Генерация идей и brainstorming
- Creative writing (рассказы, стихи)
- Нестандартные решения задач
- Маркетинговые слоганы и названия
- Художественные описания

```

   - Управление сессиями
   - Автоматическая очистка старых данных

### Парсинг ответов (3-уровневая стратегия)

**JSON:**
1. Прямой `json.loads()`
2. Извлечение из markdown блока ` ```json...``` `
3. Fallback через regex

**XML:**
1. Прямой `ET.fromstring()`
2. Извлечение из markdown блока ` ```xml...``` `
3. Fallback через regex

### Формат структурированных данных

Все ответы содержат три обязательных поля:
- `datetime` - текущая дата/время в ISO 8601 (2025-11-05T14:30:00)
- `question` - краткая тема вопроса пользователя
- `answer` - полный текстовый ответ от AI

## Устранение неполадок

### Ошибка парсинга
Если бот показывает ошибку парсинга:
- Проверьте логи в консоли
- Yandex GPT иногда возвращает ответы с markdown
- Fallback парсинг должен обрабатывать большинство случаев

### Режим не сохраняется
- Режимы хранятся в памяти
- После перезапуска бота все пользователи вернутся к режиму TEXT

### HTTP ошибки Yandex GPT
- **401**: Проверьте `YANDEX_API_KEY` и права сервисного аккаунта
- **400**: Проверьте `YANDEX_FOLDER_ID`
- **429**: Превышен лимит запросов, подождите

## MCP Integration ⚡ NEW!

Бот поддерживает работу с **Model Context Protocol (MCP)** для расширения функциональности через подключение внешних инструментов.

### Что такое MCP?

MCP (Model Context Protocol) - это открытый протокол от Anthropic для стандартизации взаимодействия между LLM-приложениями и внешними инструментами. Он позволяет подключать AI-агентов к различным источникам данных и сервисам через унифицированный интерфейс.

### Команды

- `/mcp_tools` - получить список всех доступных MCP инструментов


## RAG (Retrieval Augmented Generation) ⚡ NEW!

Бот поддерживает **RAG** - семантический поиск по документам с использованием эмбеддингов для улучшения ответов DeepSeek.

### Что такое RAG?

RAG (Retrieval Augmented Generation) - это техника, которая позволяет LLM использовать контекст из внешних документов для более точных и актуальных ответов. Вместо того чтобы полагаться только на знания модели, RAG находит релевантные фрагменты документов и использует их как контекст.

### Быстрый старт с RAG

#### 1. Установите Ollama

```bash
# macOS
brew install ollama

# Linux
curl -fsSL https://ollama.com/install.sh | sh

# Загрузите модель эмбеддингов
ollama pull bge-m3

# Запустите сервер
ollama serve
```

#### 2. Добавьте документы

Поместите ваши документы (`.md` или `.txt`) в директорию `rag_docs/`:

```
rag_docs/
├── documentation/
│   └── bot_overview.md
├── guides/
│   └── getting_started.md
└── reference/
    └── api_keys.txt
```

#### 3. Индексируйте документы

```bash
python manage_index.py index
```

#### 4. Используйте в DeepSeek

Теперь DeepSeek автоматически будет использовать контекст из ваших документов при ответе на вопросы:

```
You: Как настроить бота?
Bot: [Ответ с использованием контекста из документации]
```

### CLI команды для управления индексом

```bash
# Индексация документов
python manage_index.py index

# Поиск по индексу
python manage_index.py search "как работает бот"

# Статистика индекса
python manage_index.py stats

# Проверка Ollama
python manage_index.py verify

# Очистка индекса
python manage_index.py clear
```

### Автоматическое определение RAG

Система автоматически определяет когда нужно использовать RAG на основе ключевых слов:
- "документация"
- "как работает"
- "инструкция"
- "руководство"
- "как настроить"
- и другие...
