# Руководство по контекстным диалогам

## Обзор

Бот теперь поддерживает **контекстные диалоги** - он помнит предыдущие сообщения в рамках сессии и передаёт их в Yandex GPT для получения более релевантных ответов.

---

## Как это работает

### Автоматическая передача контекста

1. При каждом сообщении бот загружает **последние 10 сообщений** из текущей сессии
2. Эти сообщения передаются в Yandex GPT API вместе с новым запросом
3. LLM использует этот контекст для формирования ответа

### Пример работы

```python
# Структура запроса к Yandex GPT API:
{
    "messages": [
        {"role": "system", "text": "Системный промпт..."},
        {"role": "user", "text": "Привет! Меня зовут Иван."},
        {"role": "assistant", "text": "Здравствуйте, Иван!"},
        {"role": "user", "text": "Какая столица Франции?"},
        {"role": "assistant", "text": "Столица Франции - Париж."},
        {"role": "user", "text": "Как меня зовут?"}  # Текущий запрос
    ]
}

# LLM видит весь контекст и отвечает: "Вас зовут Иван."
```

## Управление сессиями

### Команда /session_info

Показывает информацию о текущей сессии:

```
📊 Информация о текущей сессии

🆔 ID сессии: 57393938-7937-49a8...
📅 Начало: 2025-11-15 16:30:00
🕐 Последняя активность: 2025-11-15 16:35:22

💬 Всего сообщений: 8
👤 От вас: 4
🤖 От ассистента: 4

Бот использует последние 10 сообщений из этой сессии для контекста.
```

### Команда /new_session

Начинает новую сессию, сбрасывая контекст:

```
🆕 Новая сессия создана!

ID сессии: d6b0a193-8cee-42a7...

Теперь бот будет помнить контекст разговора в рамках этой сессии.
```

**Когда использовать:**
- Смена темы разговора
- Начало нового задания
- Нужен "свежий старт" без предыдущего контекста

### Команда /end_session

Завершает текущую сессию:

```
✅ Сессия завершена!

ID сессии: 57393938...
Сообщений в сессии: 12

Контекст текущего диалога очищен.
При следующем сообщении автоматически создастся новая сессия.
```

## Технические детали

### Код интеграции

```python
# В YandexGPTClient добавлен метод send_message_with_history:

async def send_message_with_history(
    self,
    user_message: str,
    system_prompt: str = SYSTEM_PROMPT_DEFAULT,
    conversation_history: list = None
) -> Optional[str]:
    """
    Отправка сообщения в Yandex GPT с учётом истории диалога.

    conversation_history: список словарей с полями:
        - message_text: текст сообщения
        - message_type: 'user' или 'assistant'
    """
    # Формируем messages для API
    messages = [{"role": "system", "text": system_prompt}]

    # Добавляем историю
    for msg in conversation_history:
        role = "user" if msg["message_type"] == "user" else "assistant"
        messages.append({"role": role, "text": msg["message_text"]})

    # Добавляем текущее сообщение
    messages.append({"role": "user", "text": user_message})

    # Отправляем в API
    ...
```

### Загрузка истории

```python
# В handle_message:

# Получаем историю только из текущей сессии
conversation_history = self.memory.get_conversation_history(

)

# Отправляем с контекстом

    user_message, system_prompt, conversation_history
```

## Настройка

### Изменение глубины контекста

По умолчанию используются последние **10 сообщений**. Чтобы изменить:

```python
# В bot.py, метод handle_message, строка ~475:
conversation_history = self.memory.get_conversation_history(
    user_id, chat_id,
    limit=20,  # Изменить на нужное значение
    session_id=session_id
)
```

**Рекомендации:**
- 5-10 сообщений - экономия токенов
- 10-20 сообщений - баланс (рекомендуется)
- 20+ сообщений - максимальный контекст (но дороже)

### Ограничения API

Yandex GPT имеет ограничение на количество токенов:
- Максимум токенов в запросе зависит от модели
- Больше контекста = больше токенов = выше стоимость
- При превышении лимита API вернёт ошибку

## Часто задаваемые вопросы

### Сколько сообщений хранится в сессии?

Все сообщения сессии хранятся в БД, но **только последние 10** передаются в GPT для контекста.

### Что происходит при перезапуске бота?

Все сессии и история сохраняются в SQLite. После перезапуска:
- Активная сессия остаётся активной
- История доступна
- Контекст восстанавливается автоматически

### Как полностью очистить память?

```
/clear_memory confirm  # Удаляет ВСЮ историю (все сессии)
/end_session           # Завершает только текущую сессию
```

### Видит ли бот сообщения из других сессий?

Нет! Каждая сессия изолирована. Бот передаёт в GPT только сообщения из **текущей активной сессии**.

### Можно ли вернуться к предыдущей сессии?

В текущей реализации - нет. Команда `/new_session` завершает старую сессию. Для возврата нужно было бы знать ID старой сессии.

**Возможное улучшение:** Добавить команду `/switch_session <id>` для переключения между сессиями.

## Производительность

### Влияние на скорость

- Загрузка истории из SQLite: ~2-5 мс
- Дополнительные токены в API: ~50-200 токенов (зависит от длины сообщений)
- Общее замедление: незначительное (<100ms)

### Оптимизация

1. **Уменьшить limit** - если не нужен большой контекст
2. **Очищать старые сессии** - команда `/end_session` регулярно
3. **Использовать индексы БД** - уже реализовано

## Устранение проблем

### Бот не помнит контекст

1. Проверьте, что активна сессия: `/session_info`
2. Убедитесь, что не создали новую сессию случайно
3. Проверьте логи на ошибки загрузки истории

### Ошибка "Too many tokens"

Уменьшите глубину контекста (limit) в коде или создайте новую сессию.

### Медленные ответы

Это нормально - передача контекста требует больше времени на обработку GPT.
