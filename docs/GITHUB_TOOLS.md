# GitHub MCP Tools Documentation

## Обзор

GitHub MCP сервер предоставляет три инструмента для работы с GitHub API через Model Context Protocol. Все инструменты работают с публичным GitHub REST API v3 без необходимости авторизации.

## Доступные инструменты

### 1. get_user_info

Получение подробной информации о пользователе GitHub.

#### Параметры

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `username` | string | Да | Имя пользователя GitHub (например, 'torvalds', 'octocat') |

#### Пример запроса

```json
{
  "username": "torvalds"
}
```

#### Возвращаемая информация

- Логин и полное имя пользователя
- Биография (bio)
- Местоположение
- Количество публичных репозиториев
- Количество подписчиков (followers) и подписок (following)
- Дата создания аккаунта
- URL профиля

#### Примеры использования

**На естественном языке (DeepSeek):**
- "Покажи информацию о пользователе GitHub torvalds"
- "Расскажи о профиле octocat на GitHub"
- "Кто такой пользователь microsoft на GitHub?"

---

### 2. get_user_repositories

Получение списка публичных репозиториев пользователя.

#### Параметры

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `username` | string | Да | Имя пользователя GitHub |

#### Пример запроса

```json
{
  "username": "octocat"
}
```

#### Возвращаемая информация

Для каждого репозитория:
- Полное имя репозитория (owner/repo)
- Описание
- Основной язык программирования
- Количество звезд (stars)
- Количество форков (forks)
- URL репозитория

#### Ограничения

- Возвращается максимум 30 репозиториев
- Репозитории отсортированы по дате последнего обновления

#### Примеры использования

**На естественном языке (DeepSeek):**
- "Какие репозитории есть у пользователя torvalds?"
- "Покажи проекты пользователя facebook на GitHub"
- "Список репозиториев microsoft"

---

### 3. get_repository_commits

Получение информации о коммитах в репозитории.

#### Параметры

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|----------|-----|--------------|--------------|----------|
| `owner` | string | Да | - | Владелец репозитория |
| `repo` | string | Да | - | Название репозитория |
| `per_page` | integer | Нет | 30 | Количество коммитов на странице (1-100) |
| `page` | integer | Нет | 1 | Номер страницы |

#### Пример запроса

```json
{
  "owner": "torvalds",
  "repo": "linux",
  "per_page": 10,
  "page": 1
}
```

#### Возвращаемая информация

Для каждого коммита:
- SHA хеш коммита (короткая версия)
- Автор коммита
- Дата коммита
- Сообщение коммита (первая строка)

#### Примеры использования

**На естественном языке (DeepSeek):**
- "Покажи последние коммиты в репозитории torvalds/linux"
- "Какие были коммиты в facebook/react?"
- "Покажи последние 5 коммитов из microsoft/vscode"

## Множественные вызовы инструментов

DeepSeek может автоматически вызывать несколько инструментов для комплексных запросов.

### Примеры комбинированных запросов

**Пример 1: Профиль + репозитории**
```
Запрос: "Расскажи о пользователе octocat и покажи его репозитории"

DeepSeek вызовет:
1. get_user_info(username="octocat")
2. get_user_repositories(username="octocat")

Результат: Комплексный ответ с профилем и списком репозиториев
```

**Пример 2: Сравнение пользователей**
```
Запрос: "Сравни количество репозиториев у octocat и torvalds"

DeepSeek вызовет:
1. get_user_repositories(username="octocat")
2. get_user_repositories(username="torvalds")

Результат: Сравнительный анализ количества репозиториев
```

**Пример 3: Полный анализ репозитория**
```
Запрос: "Расскажи о репозитории facebook/react и покажи последние коммиты"

DeepSeek может вызвать:
1. get_user_info(username="facebook")
2. get_user_repositories(username="facebook")
3. get_repository_commits(owner="facebook", repo="react", per_page=10)

Результат: Полная информация о репозитории с последними коммитами
```

## Обработка ошибок

### 404 Not Found
Пользователь или репозиторий не найден.

**Сообщение:**
```
❌ Ошибка: Пользователь или репозиторий не найден. Проверьте правильность имени.
```

### 403 Rate Limit Exceeded
Превышен лимит запросов (60/час для неавторизованных запросов).

**Сообщение:**
```
❌ Ошибка: Превышен лимит запросов к GitHub API (60/час для неавторизованных запросов).
Попробуйте позже. Reset time: [timestamp]
```

### 422 Validation Failed
Невалидные параметры запроса.

**Сообщение:**
```
❌ Ошибка: Невалидные параметры запроса. Проверьте корректность данных.
```

### Timeout
Превышено время ожидания ответа от GitHub API (30 секунд).

**Сообщение:**
```
❌ Ошибка: Превышено время ожидания ответа от GitHub API (30 сек). Попробуйте позже.
```

## Ограничения GitHub API

### Rate Limits
- **Без авторизации**: 60 запросов в час
- **С авторизацией**: 5000 запросов в час (не реализовано в текущей версии)

### Pagination
- `get_user_repositories`: максимум 30 репозиториев
- `get_repository_commits`: до 100 коммитов на запрос (параметр `per_page`)

### Timeout
- Все запросы имеют таймаут 30 секунд

## Best Practices

1. **Проверяйте rate limit**: При частых запросах следите за лимитами GitHub API
2. **Кешируйте результаты**: Для часто запрашиваемых данных используйте кеширование
3. **Обрабатывайте ошибки**: Всегда проверяйте ответы на наличие ошибок
4. **Используйте pagination**: Для больших списков используйте параметры `per_page` и `page`
