### Баг #1: Первоначальная сводка не создаётся

**Проблема:**
При создании ассистента вместо сводки по последним 100 сообщениям пользователь получает вопрос от нейросети:
```
"Я понимаю, что вы хотите получить сводку... Однако для использования инструмента
анализа сообщений мне нужно знать конкретный временной период..."
```

**Причина:**
Промпт для LLM не был достаточно директивным. LLM думал, что ему нужно уточнить параметры у пользователя, вместо того чтобы сразу вызвать MCP tool `get_chat_messages`.

**Решение:**
Обновлены системные промпты в `scheduler/tasks.py`:

**Изменения в `_build_initial_summary_prompt()` (строки 466-476):**
```python
base_prompt = (
    "Ты - ассистент для анализа сообщений из Telegram чатов.\n\n"
    "У тебя есть доступ к инструменту get_chat_messages, который позволяет "
    "получить сообщения из чата за указанный период.\n\n"
    "Сейчас ты создаёшь ПЕРВОНАЧАЛЬНУЮ СВОДКУ по последним сообщениям из чата.\n\n"
    "ВАЖНО: Пользователь УЖЕ указал все параметры. Твоя задача:\n"
    f"1. НЕМЕДЛЕННО вызови инструмент get_chat_messages с параметрами из user message\n"
    "2. Проанализируй полученные сообщения\n"
    "3. Создай обзорную сводку, которая познакомит пользователя с контекстом чата\n\n"
    "НЕ задавай пользователю вопросы об уточнении параметров - все параметры уже переданы в user message.\n"
    "НЕ уточняй временной период - используй параметры from_date и to_date из user message.\n\n"
)
```

**Изменения в `_build_system_prompt()` (строки 193-202):**

### Баг #2: Автоматические сводки не приходят через интервал

**Проблема:**
Пользователь установил интервал 1 минута, но сводки не приходят автоматически через минуту.

**Причины:**

1. **При создании ассистента `last_run_at` устанавливался в `datetime.now()`** (scheduler/manager.py:135)
   - Это сбивало логику планировщика с толку

2. **При восстановлении задач после перезапуска бота время первого запуска пересчитывалось** (scheduler/manager.py:376)
   - Вместо использования `last_run_at + интервал`, всегда вычислялось `сейчас + интервал`
   - Это приводило к тому, что задачи постоянно "откладывались" при каждом перезапуске

3. **После выполнения задачи `next_run_at` не обновлялся** (scheduler/tasks.py:133)
   - Использовалось старое значение из БД вместо актуального из планировщика

**Решения:**

#### Исправление #1: Не устанавливать `last_run_at` при создании
**Файл:** `scheduler/manager.py` (строки 131-138)

**Было:**
```python
database.update_last_run(
    assistant.assistant_id,
    last_run_at=datetime.now(),
    next_run_at=job.next_run_time.replace(tzinfo=None)
)
```

**Стало:**
```python
database.update_last_run(
    assistant.assistant_id,
    last_run_at=None,  # Задача ещё не запускалась
    next_run_at=job.next_run_time.replace(tzinfo=None)
)
```

#### Исправление #2: Правильное восстановление задач
**Файл:** `scheduler/manager.py` (строки 373-413)

**Добавлена логика вычисления `start_time` на основе `last_run_at`:**
```python
for assistant in active_assistants:
    try:
        # Вычисляем время следующего запуска на основе last_run_at
        start_time = None
        if assistant.last_run_at:
            # Если задача уже выполнялась, следующий запуск = last_run_at + интервал
            if assistant.interval_type == 'minute':
                start_time = assistant.last_run_at + timedelta(minutes=assistant.interval_value)
            elif assistant.interval_type == 'hour':
                start_time = assistant.last_run_at + timedelta(hours=assistant.interval_value)
            elif assistant.interval_type == 'day':
                start_time = assistant.last_run_at + timedelta(days=assistant.interval_value)
            else:  # custom
                start_time = assistant.last_run_at + timedelta(minutes=assistant.interval_value)

            # Если вычисленное время уже прошло, запускаем немедленно
            if start_time < datetime.now():
                start_time = datetime.now() + timedelta(seconds=10)  # Запуск через 10 секунд

        # Пересоздаём задачу в планировщике с правильным start_time
        job_id = self._add_scheduler_job(assistant, start_time)
        ...
```

#### Исправление #3: Обновление `next_run_at` после выполнения
**Файл:** `scheduler/tasks.py` (строки 129-146)

**Было:**
```python
database.update_last_run(
    assistant_id=assistant_id,
    last_run_at=to_date,
    next_run_at=assistant.next_run_at  # Старое значение из БД!
)
```

**Стало:**
```python
# Получаем актуальное время следующего запуска из планировщика
from .context import get_context as get_scheduler_context
scheduler_context = get_scheduler_context()
next_run_at = None

if scheduler_context.telegram_bot and hasattr(scheduler_context.telegram_bot, 'scheduler_manager'):
    scheduler = scheduler_context.telegram_bot.scheduler_manager.scheduler
    job_id = f"assistant_{assistant_id}"
    job = scheduler.get_job(job_id)
    if job and job.next_run_time:
        next_run_at = job.next_run_time.replace(tzinfo=None)

database.update_last_run(
    assistant_id=assistant_id,
    last_run_at=to_date,
    next_run_at=next_run_at  # Актуальное значение из планировщика!
)
```

**Файлы:**
- `scheduler/manager.py` (строки 131-138, 373-413)
- `scheduler/tasks.py` (строки 129-146)

**Результат:**
✅ Автоматические сводки теперь приходят точно по расписанию
✅ Интервалы корректно соблюдаются даже после перезапуска бота
✅ `/list_assistants` показывает правильное время следующего запуска
