# Режим сравнения RAG для DeepSeek

## Описание функциональности

Режим сравнения RAG (Retrieval-Augmented Generation) позволяет пользователям оценить эффективность использования RAG в реальном времени при работе с моделью DeepSeek. При включении этого режима бот генерирует два ответа на каждый вопрос:

1. **Без RAG** - ответ основан только на знаниях модели
2. **С RAG** - ответ обогащен контекстом из проиндексированных документов

После генерации обоих ответов система автоматически анализирует метрики и определяет, в каких случаях RAG был полезен, а где не добавил значимой ценности.

## Возможности

### Основные функции

- ✅ Интерактивное включение/выключение режима командой `/rag`
- ✅ Генерация двух ответов на каждый запрос
- ✅ Автоматический сбор метрик (токены, время, релевантность)
- ✅ Интеллектуальный анализ эффективности RAG
- ✅ Статистика использования режима
- ✅ Работает только с моделью DeepSeek

### Метрики

Для каждого ответа собираются следующие метрики:

- **Количество токенов** - подсчет с использованием tiktoken (fallback на приблизительный подсчет)
- **Время генерации** - в секундах с точностью до 2 знаков
- **Количество использованных чанков** (только для RAG)
- **Средняя релевантность чанков** (только для RAG)

### Автоматический анализ

Система автоматически определяет эффективность RAG на основе:

1. **Релевантность документов**:
   - Высокая (> 0.7) - RAG определенно помог
   - Средняя (0.5 - 0.7) - RAG вероятно помог
   - Низкая (< 0.5) - RAG не был эффективен

2. **Изменение длины ответа**:
   - Увеличение > 50 токенов - RAG добавил информации
   - Уменьшение - возможно, RAG не нужен

3. **Тип вопроса**:
   - Общие вопросы (приветствия, определения) - RAG не нужен
   - Специфичные вопросы - RAG может помочь

## Архитектура решения

### Компоненты

```
┌─────────────────────────────────────────────────────────┐
│                      TelegramBot                         │
│  ┌────────────────┐  ┌─────────────────────────────┐   │
│  │  /rag command  │  │  handle_message()           │   │
│  │                │  │  (с проверкой режима)       │   │
│  └────────┬───────┘  └──────────────┬──────────────┘   │
│           │                          │                   │
│           v                          v                   │
│  ┌──────────────────────────────────────────────────┐  │
│  │         RAGStateManager                          │  │
│  │  - Хранит состояния пользователей               │  │
│  │  - Управляет включением/выключением режима       │  │
│  │  - Собирает статистику                          │  │
│  └───────────────────────┬──────────────────────────┘  │
│                          │                              │
└──────────────────────────┼──────────────────────────────┘
                           │
           ┌───────────────v────────────────┐
           │      RAGComparator             │
           │  - Генерирует два ответа       │
           │  - Координирует процесс        │
           └───────────────┬────────────────┘
                           │
          ┌────────────────┼────────────────┐
          │                │                │
          v                v                v
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ DeepSeek     │  │ Metrics      │  │ RAG         │
│ Provider     │  │ Collector    │  │ Analyzer    │
│              │  │              │  │             │
│ -generate()  │  │ -measure()   │  │ -analyze()  │
│ без RAG      │  │ -compare()   │  │             │
│              │  │              │  │             │
│ -generate()  │  │              │  │             │
│ с RAG        │  │              │  │             │
└──────────────┘  └──────────────┘  └──────────────┘
```

### Поток данных

1. **Пользователь** отправляет сообщение
2. **Bot.handle_message()** проверяет режим через **RAGStateManager**
3. Если режим включен:
   - Вызывается **RAGComparator.compare_responses()**
   - Генерируются два ответа через **DeepSeekProvider**
   - **MetricsCollector** собирает метрики для обоих ответов
   - **RAGAnalyzer** анализирует эффективность
   - **RAGComparator** форматирует результат
4. Результат отправляется пользователю
5. Статистика записывается в **RAGStateManager**

## Технические детали

### Управление состоянием RAG

Модуль `utils/state_manager.py` содержит:

- **RAGStateManager** - синглтон для управления состояниями всех пользователей
- **UserRAGState** - dataclass с состоянием одного пользователя

Состояние включает:
- `rag_comparison_mode` - включен ли режим
- `last_comparison_time` - время последнего сравнения
- `statistics` - статистика сравнений

### Сбор метрик

Модуль `rag/metrics.py` содержит:

- **MetricsCollector** - сборщик метрик
- **ResponseMetrics** - метрики одного ответа
- **ComparisonMetrics** - метрики сравнения двух ответов
- **PerformanceTimer** - таймер для измерения времени

Подсчет токенов:
```python
import tiktoken  # если доступен
# fallback: ~1.33 токена на слово
```

### Анализ эффективности

Модуль `rag/comparison.py` содержит:

- **RAGAnalyzer** - анализатор эффективности RAG
- **RAGComparator** - координатор процесса сравнения
- **ComparisonResult** - результат сравнения

Критерии определения полезности RAG:
- Релевантность чанков > 0.7
- Увеличение длины ответа > 50 токенов
- Отсутствие общих ключевых слов в вопросе

## Обработка ошибок

Система обрабатывает следующие ошибки:

1. **Режим недоступен**:
   - Пользователь не использует DeepSeek
   - RAG Manager не инициализирован
   - Ollama не запущен

2. **Ошибки генерации**:
   - Таймаут при генерации ответа
   - Ошибка подключения к API
   - Ошибка RAG поиска

3. **Graceful degradation**:
   - При ошибке в режиме сравнения, возвращается к обычному режиму
   - Уведомление пользователя об ошибке
   - Логирование для отладки

## Конфигурация

Параметры RAG настраиваются в `config/embeddings_config.yaml`:

```yaml
deepseek_integration:
  context_chunks: 3              # Количество чанков для контекста
  max_context_tokens: 2000       # Максимум токенов в контексте
  rag_keywords:                  # Ключевые слова для RAG
    - "документация"
    - "как работает"
    - "инструкция"
    # ...

search:
  top_k: 3                      # Количество результатов поиска
  min_similarity: 0.6           # Минимальная релевантность
```

## Ограничения

1. **Только DeepSeek**: Режим работает только с моделью DeepSeek
2. **Требует Ollama**: Для эмбеддингов необходим запущенный Ollama
3. **Производительность**: Генерация двух ответов занимает ~2x времени
4. **Проиндексированные документы**: RAG работает только с заранее проиндексированными документами

## Метрики производительности

Типичное время выполнения:
- Генерация без RAG: 2-4 секунды
- Генерация с RAG: 3-5 секунд (+ время поиска)
- Общее время сравнения: 5-9 секунд

Память:
- Состояние одного пользователя: ~1KB
- Результат одного сравнения: ~5KB

## FAQ

**Q: Зачем нужен режим сравнения?**
A: Чтобы пользователи могли оценить, насколько RAG улучшает ответы в их конкретных случаях использования.

**Q: Почему только DeepSeek?**
A: DeepSeek - единственный провайдер в боте с интегрированным RAG.

**Q: Можно ли использовать параллельно?**
A: Да, разные пользователи могут независимо использовать режим сравнения.

**Q: Сохраняются ли результаты сравнений?**
A: В памяти хранится только статистика (количество сравнений, полезность). Полные результаты не сохраняются.

**Q: Как отключить режим?**
A: Просто используйте команду `/rag` еще раз для переключения режима.

## Поддержка

При возникновении проблем:

1. Проверьте, что DeepSeek Provider инициализирован
2. Убедитесь, что Ollama запущен
3. Проверьте наличие проиндексированных документов
4. Просмотрите логи для деталей ошибок

Логи находятся в stdout бота и содержат информацию о каждом шаге сравнения.
