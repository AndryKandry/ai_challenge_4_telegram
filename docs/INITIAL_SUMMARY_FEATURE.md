# Доработка: Первоначальная сводка при создании ассистента

**Дата:** 19.11.2025
**Статус:** ✅ Реализовано

---

## 📋 Описание

При создании нового ассистента система теперь автоматически создаёт **первоначальную сводку** по последним 100 сообщениям из чата/канала.

Это позволяет пользователю сразу получить контекст и понять, о чём этот чат, не дожидаясь первого планового запуска.

---

## 🎯 Функциональность

### Что происходит при создании ассистента:

1. **Создание ассистента** - сохранение в БД, запуск планировщика
2. **Уведомление пользователя** - "⏳ Создаю первоначальную сводку..."
3. **Асинхронный запуск** - первоначальная сводка создаётся в фоне
4. **Получение последних 100 сообщений** - через MCP tool `get_chat_messages`
5. **Анализ через DeepSeek** - специальный промпт для первоначальной сводки
6. **Отправка сводки пользователю** - с эмодзи 🎉 и информацией о запуске

### Особенности первоначальной сводки:

- **Количество сообщений:** 100 (последние)
- **Период:** последние 7 дней
- **Промпт:** специальный, фокусируется на общем обзоре чата
- **Формат:** отличается от обычных периодических сводок
- **Асинхронность:** не блокирует создание ассистента

## 🔧 Техническая реализация

### Изменённые файлы:

**1. `scheduler/manager.py`**
- Добавлен вызов `execute_initial_summary()` после создания ассистента
- Запуск через `asyncio.create_task()` для неблокирующего выполнения
- Error handling - ошибка первоначальной сводки не прерывает создание ассистента

**2. `scheduler/tasks.py`**
- Новая функция `execute_initial_summary()` - выполнение первоначальной сводки
- Новая функция `_build_initial_summary_prompt()` - специальный промпт
- Новая функция `_format_initial_summary()` - форматирование с эмодзи 🎉
- Обновлена `_build_user_prompt()` - добавлен параметр `limit`

### Архитектура:

```
User → /telegram_assistant
         ↓
SchedulerManager.create_assistant()
         ↓
   [1] Создание в БД
   [2] Запуск планировщика
   [3] asyncio.create_task(execute_initial_summary())  ← Асинхронно!
         ↓
         return success → User: "✅ Ассистент создан"

         [Параллельно выполняется:]

         execute_initial_summary()
         ↓
   [1] Уведомление: "⏳ Создаю первоначальную сводку..."
   [2] DeepSeek → MCP: get_chat_messages(limit=100)
   [3] MCP → Telegram API: последние 100 сообщений
   [4] DeepSeek: анализ с специальным промптом
   [5] Форматирование сводки
   [6] Отправка: "🎉 Первоначальная сводка..."
   [7] Сохранение в execution_history
```

## 📊 Отличия от обычных сводок

| Параметр | Обычная сводка | Первоначальная сводка |
|----------|----------------|------------------------|
| **Триггер** | По расписанию (APScheduler) | При создании ассистента |
| **Период** | С последнего запуска до сейчас | Последние 7 дней |
| **Лимит сообщений** | 1000 | 100 |
| **Промпт** | Анализ новых сообщений | Общий обзор чата |
| **Формат** | "📊 Сводка из чата" | "🎉 Первоначальная сводка" |
| **Дополнительно** | Время следующей сводки | "✅ Ассистент запущен" |

## ⚙️ Настройка

### Изменение количества сообщений:

По умолчанию анализируется **100 последних сообщений**. Для изменения:

**Вариант 1:** В команде бота (будущее расширение)
```python
# В bot.py можно добавить параметр
message_limit = 200  # вместо 100
```

**Вариант 2:** В коде напрямую
```python
# scheduler/manager.py:144
asyncio.create_task(execute_initial_summary(
    assistant_id=assistant.assistant_id,
    database=self.database,
    llm_provider=self.llm_provider,
    telegram_bot_instance=self.telegram_bot,
    message_limit=200  # Измените здесь
))
```

### Изменение периода:

По умолчанию берутся сообщения за **последние 7 дней**. Для изменения:

```python
# scheduler/tasks.py:327
from_date = to_date - timedelta(days=30)  # Вместо 7
```

## 🐛 Обработка ошибок

### Сценарии:

1. **Чат не найден / нет доступа**
   - Пользователь получает: "❌ Не удалось создать первоначальную сводку"
   - Ассистент всё равно создан и будет работать по расписанию
   - Ошибка логируется и сохраняется в `execution_history`

2. **LLM не вернул ответ**
   - Аналогично пункту 1
   - Retry не выполняется (это первоначальная сводка)

3. **Timeout при анализе**
   - Ошибка ловится и логируется
   - Пользователь уведомляется
   - Ассистент продолжает работать

4. **Недостаточно сообщений**
   - LLM сообщит: "В чате мало сообщений"
   - Сводка всё равно отправляется

## ✅ Преимущества

1. **Мгновенный контекст** - пользователь сразу видит, о чём чат
2. **Не блокирует создание** - выполняется асинхронно
3. **Отдельный промпт** - специально для обзора, а не инкрементальных изменений
4. **Сохраняется в истории** - можно отследить в `execution_history`
5. **Graceful failure** - ошибка не ломает создание ассистента
