# Формат кликабельных ссылок на источники

## Обзор

Документ описывает формат представления кликабельных ссылок на источники документов в ответах RAG-системы для модели DeepSeek с возможностью открытия документов через MCP-сервер filesystem.py.

## Назначение

Кликабельные ссылки позволяют:
- Быстро переходить к исходным документам
- Проверять информацию из ответов модели
- Открывать документы в нужном месте (по номеру строки)
- Повышать доверие к ответам AI

## Формат отображения в Telegram

### Базовый формат

```markdown
📚 **Источники:**
1. {emoji} [{filename}]({mcp_link}) - строки {lines} (релевантность: {relevance})
2. {emoji} [{filename}]({mcp_link}) - строки {lines} (релевантность: {relevance})
...

💡 *Нажмите на ссылку чтобы открыть документ через MCP*
```

### Компоненты ссылки

#### 1. Эмодзи типа файла

Визуальный индикатор типа документа:

| Расширение | Эмодзи | Описание |
|------------|--------|----------|
| `.txt`     | 📄     | Текстовый файл |
| `.md`      | 📝     | Markdown документ |
| `.markdown`| 📝     | Markdown документ |
| `.py`      | 🐍     | Python файл |
| `.js`      | 🟨     | JavaScript файл |
| `.json`    | 📋     | JSON файл |
| `.yaml`    | 📄     | YAML файл |

#### 2. Имя файла

- Отображается в квадратных скобках `[filename.md]`
- Максимальная длина: 30 символов (настраивается)
- Длинные имена обрезаются: `[very_long_filename...md]`
- Сохраняется расширение файла

**Примеры:**
```
[document.md]
[getting_started.txt]
[api_reference...md]  // обрезанное имя
```

#### 3. MCP URI ссылка

Ссылка в формате Model Context Protocol для открытия файла.

**Синтаксис:**
```
mcp://filesystem/{url_encoded_path}#lines={start}-{end}
```

**Компоненты:**
- `mcp://` - схема протокола
- `filesystem` - имя сервиса (filesystem server)
- `{url_encoded_path}` - URL-encoded абсолютный путь
- `#lines={start}-{end}` - опциональный фрагмент с номерами строк

**Примеры:**
```
mcp://filesystem/%2Fpath%2Fto%2Fdocument.md#lines=15-25
mcp://filesystem/%2Frag_docs%2Fguides%2Fgetting_started.txt#lines=1-10
mcp://filesystem/%2Fpath%2Fmy%20document.md#lines=5-15
```

#### 4. Номера строк

Диапазон строк, откуда взята информация:

**Формат:** `строки {start}-{end}`

**Примеры:**
```
строки 1-10
строки 15-25
строки 42-58
```

**Определение номеров строк:**
1. **Из метаданных** - точные `char_start` и `char_end`
2. **Аппроксимация** - ~50 символов на строку
3. **Fallback** - на основе `chunk_index`

#### 5. Релевантность

Показатель релевантности источника к запросу:

**Формат:** `(релевантность: {percentage})`

**Диапазон:** 0% - 100%

**Расчет:**
```python
relevance = max(similarity_score, rerank_score) * 100
```

**Примеры:**
```
(релевантность: 95%)
(релевантность: 87%)
(релевантность: 72%)
```

## Поддерживаемые типы документов

### TXT файлы

**Расширение:** `.txt`

**Эмодзи:** 📄

**Особенности:**
- Простой текстовый формат
- Кодировка: UTF-8 (по умолчанию)
- Максимальный размер: 10 MB
- Поддержка: полная

**Пример:**
```
📄 [readme.txt](mcp://filesystem/...) - строки 1-15 (релевантность: 90%)
```

### MD файлы (Markdown)

**Расширения:** `.md`, `.markdown`

**Эмодзи:** 📝

**Особенности:**
- Markdown форматирование
- Сохранение структуры заголовков
- Кодировка: UTF-8 (по умолчанию)
- Максимальный размер: 10 MB
- Поддержка: полная

**Пример:**
```
📝 [guide.md](mcp://filesystem/...) - строки 25-45 (релевантность: 88%)
```

## Ограничения и правила

### Количество источников

- **По умолчанию:** 5 источников
- **Минимум:** 1 источник
- **Максимум:** Настраивается через `default_sources_count`

**Конфигурация:**
```yaml
citation:
  default_sources_count: 5
```

### Длина имени файла

- **По умолчанию:** 30 символов
- **Обрезание:** `filename...ext`
- **Сохранение:** расширение всегда сохраняется

**Конфигурация:**
```yaml
mcp_links:
  max_filename_length: 30
```

### Фильтрация источников

Автоматическая фильтрация по:
1. **Поддерживаемым расширениям** - только .txt, .md, .markdown
2. **Релевантности** - минимальная релевантность (настраивается)
3. **Доступности** - файл должен существовать

## Настройка форматирования

### Конфигурация в embeddings_config.yaml

```yaml
# Настройки цитирования
citation:
  enabled: true                     # Включить цитирование
  default_sources_count: 5          # Количество источников

# Настройки MCP ссылок
mcp_links:
  enabled: true                     # Включить кликабельные ссылки
  server_url: "http://localhost:8003"
  supported_extensions:
    - ".txt"
    - ".md"
    - ".markdown"
  max_filename_length: 30
```

### Программная настройка

```python
from src.rag_integration import RAGManager

rag_manager = RAGManager()

# Форматирование с кастомными параметрами
sources = rag_manager.format_clickable_sources(
    search_results=results,
    max_sources=3,                  # Только 3 источника
    title="📖 **Документы:**"       # Кастомный заголовок
)
```

## Обработка специальных случаев

### Нет источников

Если RAG не нашел релевантных документов:

```markdown
Ответ модели без использования RAG.

(Источники не указываются)
```

### Нет поддерживаемых файлов

Если все найденные файлы имеют неподдерживаемые форматы:

```markdown
📚 **Использованные источники RAG:**
1. `document.pdf` (релевантность: 0.95)
2. `spreadsheet.xlsx` (релевантность: 0.87)
```

Fallback на обычный формат без кликабельных ссылок.

### Ошибка генерации ссылки

При ошибке генерации MCP URI:

```markdown
📄 document.md - строки 1-10
```

Fallback на простой текстовый формат.

### Файл с пробелами в имени

```markdown
📝 [my document.md](mcp://filesystem/%2Fpath%2Fmy%20document.md#lines=1-10)
```

Пробелы автоматически кодируются в `%20`.

### Длинное имя файла

```markdown
📝 [very_long_filename_that_...md](mcp://filesystem/...) - строки 1-10
```

Обрезается до 30 символов с сохранением расширения.

## Интеграция с Telegram

### Markdown форматирование

Telegram поддерживает Markdown для форматирования сообщений.

**Используемые элементы:**
- `**bold**` - жирный текст для заголовков
- `[text](url)` - кликабельные ссылки
- `*italic*` - курсив для примечаний

**Пример кода:**
```python
# Отправка в Telegram
await update.message.reply_text(
    formatted_sources,
    parse_mode="Markdown"  # или "MarkdownV2"
)
```

### Ограничения Telegram

1. **Максимальная длина сообщения:** 4096 символов
2. **Схемы URL:** Telegram не поддерживает нативно mcp://
3. **Отображение:** MCP ссылки отображаются как текст

**Решение:**
- Использовать MCP-совместимые клиенты
- Или интегрировать web-based предпросмотр

## Примеры использования в коде

### Генерация одной ссылки

```python
from src.integrations.mcp_link_generator import MCPLinkGenerator

generator = MCPLinkGenerator(
    mcp_server_url="http://localhost:8003"
)

# Генерация ссылки
link = generator.generate_file_link(
    file_path="/path/to/document.md",
    line_numbers="15-25"
)

print(link)
# mcp://filesystem/%2Fpath%2Fto%2Fdocument.md#lines=15-25
```

### Форматирование источника

```python
formatted = generator.format_clickable_source(
    source_file="/path/to/document.md",
    chunk_id="document_md_chunk_0",
    line_numbers="15-25",
    relevance="92%",
    max_filename_length=30
)

print(formatted)
# 📝 [document.md](mcp://filesystem/...) - строки 15-25 (релевантность: 92%)
```

### Форматирование списка источников

```python
from src.rag_integration import RAGManager

rag_manager = RAGManager()

# Поиск
_, sources = rag_manager.enrich_message_with_rag(
    user_message="Как работает бот?",
    use_reranking=True
)

# Форматирование
clickable_sources = rag_manager.format_clickable_sources(
    search_results=sources,
    max_sources=5,
    title="📚 **Источники:**"
)

print(clickable_sources)
```

## Troubleshooting

### Ссылки не кликабельны

**Причина:** Telegram отображает mcp:// как текст

**Решение:**
- Используйте MCP-совместимый клиент
- Или добавьте web-based предпросмотр

### Некорректные номера строк

**Причина:** Аппроксимация при отсутствии метаданных

**Решение:**
1. Обновите индексатор для сохранения точных номеров
2. Переиндексируйте документы

```bash
python manage_index.py index --force
```

### Файл не найден

**Причина:** Файл удален или перемещен после индексации

**Решение:**
1. Переиндексируйте документы
2. Проверьте наличие файла
3. Обновите конфигурацию путей

### Слишком длинное сообщение

**Причина:** Превышен лимит Telegram (4096 символов)

**Решение:**
1. Уменьшите `max_sources`
2. Укоротите заголовок
3. Реализуйте пагинацию

```python
# Ограничение источников
sources = rag_manager.format_clickable_sources(
    search_results=results,
    max_sources=3  # вместо 5
)
```
