# Исправление багов - 20 ноября 2025 (v1.2.2)

## Обнаруженные проблемы

### 1. Ошибка "unable to open database file" при первоначальной сводке

**Симптомы:**
- При попытке получить первоначальную сводку из чата пользователь получал сообщение об ошибке вместо сводки
- В логах MCP сервера: `ERROR - Ошибка запуска Telegram клиента: unable to open database file`

**Причина:**
В `mcp_server/telegram_assistant.py` при создании Pyrogram Client указывалась директория `workdir="data"` для хранения session файлов, но эта директория не создавалась автоматически при первом запуске. SQLite база данных Pyrogram не могла быть создана из-за отсутствия родительской директории.

**Решение:**
Добавлено автоматическое создание директории перед инициализацией клиента:

```python
# Создаём директорию data, если её нет
data_dir = "data"
os.makedirs(data_dir, exist_ok=True)
logger.info(f"Директория для session файлов: {data_dir}")
```

**Файлы:** `mcp_server/telegram_assistant.py:72-75`

### 2. Автоматические сводки не приходили по расписанию

**Симптомы:**
- Ассистент создавался успешно, интервал устанавливался (например, 1 минута)
- В логах видно, что задача добавлена в планировщик с корректным `next_run_time`
- Но после наступления времени выполнения никаких записей о запуске задачи не появлялось
- Сводки не приходили пользователю

**Логи (пример):**
```
2025-11-20 00:58:16,845 - scheduler.manager - INFO - Задача assistant_6e045cd5... добавлена в планировщик с первым запуском в 2025-11-20 00:59:18.015923
# После 00:59:18 - тишина, никаких записей о выполнении
```

**Причина:**
APScheduler работал корректно и пытался выполнять задачи, но отсутствовало логирование событий выполнения (job executed, job error, job missed). Из-за этого было невозможно определить, выполняются ли задачи на самом деле, или происходят ошибки при выполнении.

Также было недостаточно диагностической информации о состоянии задач после добавления в планировщик.

**Решение:**

#### 2.1. Добавлены Event Listeners для APScheduler

Добавлены три слушателя событий для мониторинга выполнения задач:

```python
from apscheduler.events import EVENT_JOB_EXECUTED, EVENT_JOB_ERROR, EVENT_JOB_MISSED

# В __init__:
self.scheduler.add_listener(self._job_executed_listener, EVENT_JOB_EXECUTED)
self.scheduler.add_listener(self._job_error_listener, EVENT_JOB_ERROR)
self.scheduler.add_listener(self._job_missed_listener, EVENT_JOB_MISSED)

def _job_executed_listener(self, event):
    """Слушатель успешного выполнения задачи."""
    logger.info(f"✅ Job {event.job_id} выполнен успешно")

def _job_error_listener(self, event):
    """Слушатель ошибок выполнения задачи."""
    logger.error(f"❌ Job {event.job_id} завершился с ошибкой: {event.exception}")

def _job_missed_listener(self, event):
    """Слушатель пропущенных задач."""
    logger.warning(f"⚠️ Job {event.job_id} пропущен (misfire)")
```

**Файлы:** `scheduler/manager.py:18, 63-67, 75-85`

#### 2.2. Улучшена диагностика при добавлении задачи

После добавления задачи в планировщик теперь выполняется проверка её состояния:

```python
# Дополнительная диагностика
job = self.scheduler.get_job(job_id)
if job:
    logger.info(f"Задача {job_id} проверка: next_run_time={job.next_run_time}, trigger={job.trigger}")
else:
    logger.error(f"Задача {job_id} не найдена сразу после добавления!")
```

**Файлы:** `scheduler/manager.py:216-221`

#### 2.3. Улучшено логирование в execute_task

Добавлено более информативное логирование в начале выполнения задачи:

```python
started_at = datetime.now()
logger.info(f"🚀 ЗАПУСК ЗАДАЧИ: assistant_id={assistant_id}, время={started_at}")
# ...
logger.info(f"Контекст получен для ассистента {assistant_id}")
```

**Файлы:** `scheduler/tasks.py:34-35, 47`

### 3. Блокировка при создании первоначальной сводки

**Симптомы:**
- Работа бота "зависает" на сообщении "Создаю первоначальную сводку из чата..."
- В логах MCP сервера появляется: `Enter phone number or bot token:`
- Первоначальная сводка никогда не создаётся

**Причина:**
Pyrogram требует интерактивную авторизацию при первом запуске для создания session файла. Это блокирует работу MCP сервера, который запущен в фоновом режиме и не может принимать интерактивный ввод.

**Решение:**
Создан отдельный скрипт `setup_telegram_session.py` для предварительной авторизации:

```python
# Интерактивный скрипт для создания session файла
python setup_telegram_session.py
```

Скрипт:
1. Проверяет наличие TELEGRAM_API_ID и TELEGRAM_API_HASH в .env
2. Создаёт директорию data/ если её нет
3. Запускает интерактивную авторизацию Pyrogram
4. Сохраняет session файл в data/telegram_assistant_mcp.session
5. После этого MCP сервер работает без блокировок

**Файлы:**
- `setup_telegram_session.py` - скрипт авторизации
- `TELEGRAM_SETUP.md` - подробная инструкция

**Использование:**

```bash
# Шаг 1: Добавьте в .env
TELEGRAM_API_ID=your_api_id
TELEGRAM_API_HASH=your_api_hash

# Шаг 2: Выполните авторизацию (ОДИН РАЗ)
python setup_telegram_session.py

# Введите номер телефона, код подтверждения, пароль 2FA (если есть)

# Шаг 3: Запускайте серверы - всё работает автоматически!
python mcp_server/telegram_assistant.py
python bot.py
```
