# Обработка ошибок токенов - Документация

## Обзор

Этот документ описывает все сценарии обработки ошибок, связанных с токенами, и пользовательские сообщения.

## Типы ошибок

### 1. Превышение лимита токенов

**Код:** `token_overflow_warning`
**Модуль:** `bot.py`
**Поведение:** Предупреждение, но запрос ВСЁ РАВНО отправляется в LLM

#### Когда возникает
- Пользователь отправляет запрос > 8192 токенов (для yandexgpt-lite)
- Проверка происходит перед отправкой в Yandex GPT API

#### Обработка
```python
# В bot.py handle_message()
is_within_limit, error_msg = check_token_limit_before_request(request_tokens)
if not is_within_limit:
    # Показываем предупреждение
    await update.message.reply_text(warning_message)
    # НО продолжаем обработку - запрос отправляется в LLM!
```

#### Пользовательское сообщение
```
⚠️ Ваш запрос превышает рекомендуемый лимит!

📊 Ваш текст: ~9,500 токенов
📏 Рекомендуемый лимит: 8,192 токенов
❌ Превышение: 1,308 токенов (~16%)

⚠️ Отправляю запрос в LLM, но ответ может быть обрезан или некорректен.
Рекомендую сократить текст для лучшего результата.
```

#### Логирование
```
[WARNING] User 123456789 exceeds token limit: 9500 > 8192, but request will be sent anyway
```

#### Преимущества подхода
✅ Пользователь информирован о рисках
✅ Запрос всё равно обрабатывается (лучший UX)
✅ Конкретные рекомендации по оптимизации
✅ Точный расчет превышения
⚠️ Может привести к обрезанным или некорректным ответам от LLM

### 2. Приближение к лимиту (80-90%)

**Код:** `token_warning_high`
**Модуль:** `error_handlers.py`
**Функция:** `send_token_warning(update, context, tokens, model)`

#### Когда возникает
- Общее количество токенов (запрос + ответ) >= 80% лимита
- Показывается после успешного ответа

#### Обработка
```python
# В bot.py после получения ответа
total_tokens = request_tokens + response_tokens
percentage = total_tokens / limit

if percentage >= 0.8:
    warning_message = format_token_warning(total_tokens, limit)
    if warning_message:
        await update.message.reply_text(warning_message)
```

#### Пользовательское сообщение (80-90%)
```
⚠️ Токены: 7,500/8,192 (92%)
⚠️ ВНИМАНИЕ! Очень близко к лимиту!

⚠️ Следующий запрос такого размера может не обработаться.
Рекомендую:
• Использовать более короткие запросы
• Разбивать большие тексты на части
• Проверить статистику: /tokens_stats
```

#### Логирование
```
[INFO] Warning sent to user 123456789: 7500/8192 tokens (92%)
[INFO] User approaching token limit
```

### 3. Превышение 50-80% лимита

**Код:** `token_warning_medium`
**Визуальный индикатор:** ⚠️

#### Когда возникает
- Общее количество токенов >= 50% и < 80%

#### Обработка
- Автоматическая смена индикатора на ⚠️
- Опциональное текстовое предупреждение (в зависимости от настроек)

#### Пользовательское сообщение (если включено)
```
⚠️ Токены: 6,000/8,192 (73%)
Приближаетесь к лимиту модели.
Рекомендуется сократить следующие запросы.
```

### 4. Ошибка подсчета токенов

**Код:** `token_count_error`
**Редкость:** Низкая

#### Когда возникает
- Исключение при подсчете токенов
- Некорректные входные данные

#### Обработка
```python
try:
    tokens = self.token_counter.count_tokens(text)
except Exception as e:
    logger.error(f"Error counting tokens: {e}")
    tokens = len(text) // 4  # Fallback оценка
```

#### Логирование
```
[ERROR] Error counting tokens for user 123456789: ValueError...
[WARNING] Using fallback token estimation: 250 tokens
```

#### Последствия
- Используется примерная оценка
- Пользователь не информируется об ошибке
- Функциональность продолжает работать

### 5. Ошибка сохранения настроек

**Код:** `settings_save_error`
**Модуль:** `user_settings.py`

#### Когда возникает
- Ошибка записи в JSON файл
- Недостаточно прав доступа
- Диск заполнен

#### Обработка
```python
try:
    with open(USER_SETTINGS_FILE, 'w') as f:
        json.dump(data, f)
except Exception as e:
    logger.error(f"Error saving user settings: {e}")
    # Данные остаются в памяти
```

#### Пользовательское сообщение
Пользователь не информируется напрямую, но:
- Настройки работают в текущей сессии
- При перезапуске могут вернуться к дефолтным

#### Логирование
```
[ERROR] Error saving user settings: [Errno 28] No space left on device
[WARNING] Settings will be lost on restart
```

### 6. Ошибка загрузки настроек

**Код:** `settings_load_error`
**Модуль:** `user_settings.py`

#### Когда возникает
- JSON файл поврежден
- Файл не существует при первом запуске
- Несовместимый формат данных

#### Обработка
```python
try:
    with open(USER_SETTINGS_FILE, 'r') as f:
        data = json.load(f)
except FileNotFoundError:
    logger.info("Settings file not found, will be created")
    data = {}
except json.JSONDecodeError:
    logger.error("Corrupted settings file, using defaults")
    data = {}
```

#### Последствия
- Используются дефолтные настройки
- Пользователь не информируется
- Новые настройки будут сохранены корректно

#### Логирование
```
[INFO] Settings file not found, will be created on first save
[ERROR] Corrupted settings file, using defaults
```

## Граничные случаи

### Запрос ровно на лимите (8192 токена)

**Обработка:** Разрешен, но показано предупреждение
**Индикатор:** 🔴
**Сообщение:** Критическое предупреждение

### Пустой запрос

**Обработка:**
```python
if not text:
    return 0  # 0 токенов
```

**Последствия:** Нормальная обработка, просто 0 токенов

### Очень короткий запрос (1-2 символа)

**Обработка:** Нормальная
**Токены:** ~1 токен
**Особенности:** Нет

### Запрос с нестандартными символами

**Обработка:**
```python
words = re.findall(r'\b\w+\b', text)  # Unicode-safe regex
```

**Поддержка:**
- Emoji: подсчитываются как символы
- Специальные символы: учитываются
- Разные языки: корректная обработка

## Обработка специфических ошибок API

### API Key недействителен

**Обработка:** В основном bot.py, не в системе токенов
**Влияние на токены:** Нет - подсчет работает независимо

### API квота исчерпана

**Обработка:** API error, не связано с токенами
**Влияние:** Подсчет токенов помогает отслеживать использование

### Timeout

**Обработка:** Retry logic в основном коде
**Влияние:** Токены уже подсчитаны и залогированы

## Мониторинг и алерты

### Метрики для отслеживания

1. **Частота превышений лимита**
   - Сколько запросов блокируется
   - Средний размер превышения

2. **Распределение использования токенов**
   - Процент запросов в каждой зоне (< 50%, 50-80%, > 80%)
   - Пиковые значения

3. **Ошибки системы**
   - Ошибки сохранения/загрузки данных
   - Исключения при подсчете токенов

### Рекомендуемые действия

**Если > 10% запросов превышают лимит:**
- Добавить предупреждение в /start сообщение
- Показать примеры оптимальной длины запросов

**Если ошибки сохранения данных:**
- Проверить disk space
- Проверить permissions
- Рассмотреть миграцию на БД

## FAQ по обработке ошибок

**Q: Что происходит при превышении лимита?**
A: Запрос блокируется ДО отправки в API. Пользователь получает подробное сообщение с рекомендациями. API квота не расходуется.

**Q: Могут ли настройки пользователя потеряться?**
A: При ошибке сохранения настройки остаются в памяти до перезапуска. При следующем успешном сохранении данные будут записаны.

**Q: Что если подсчет токенов неточен?**
A: Используется примерная оценка. Для критичных сценариев планируется интеграция с официальным Tokenizer API.

**Q: Как обрабатываются множественные ошибки?**
A: Каждая ошибка логируется независимо. Пользователю показывается только критичная информация, остальное в логах.
