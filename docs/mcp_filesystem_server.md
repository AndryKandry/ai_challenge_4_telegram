# Filesystem MCP Server - Техническая документация

## Обзор

Filesystem MCP Server - это Model Context Protocol сервер, предоставляющий инструменты для безопасной работы с файловой системой компьютера. Сервер построен на базе библиотеки `fastmcp` и использует SSE (Server-Sent Events) транспорт для обеспечения стабильной работы.

## Архитектура

### Основные компоненты

1. **Валидация путей** - функция `validate_path()` обеспечивает безопасность работы с файловой системой
2. **MCP инструменты** - 6 основных инструментов для операций с файлами и директориями
3. **Система безопасности** - ограничения доступа к системным директориям и размеров файлов
4. **Логирование** - полное логирование всех операций для аудита

### Транспорт

Сервер использует **SSE (Server-Sent Events)** транспорт по умолчанию для обхода известного бага в MCP Python SDK ([#862](https://github.com/modelcontextprotocol/python-sdk/issues/862)) с stdio транспортом.

**Порт по умолчанию**: 8003
**URL**: `http://localhost:8003/sse`

## Инструменты

### 1. list_directory

Вывод содержимого указанной директории с метаинформацией.

**Параметры**:
- `path` (str, опционально): Путь к директории. По умолчанию: текущая директория (`.`)

**Возвращает**:
- Отформатированный список файлов и поддиректорий
- Для каждого элемента: тип (файл/директория), размер, дата изменения, имя
- Сортировка: сначала директории, затем файлы (по алфавиту)

**Пример вызова**:
```json
{
  "name": "list_directory",
  "arguments": {
    "path": "~/Documents"
  }
}
```

**Пример ответа**:
```
📂 Содержимое директории: /Users/username/Documents
Всего элементов: 25
================================================================================
   Тип     |     Размер |   Дата изменения    | Имя
--------------------------------------------------------------------------------
📁 DIR  |        --- | 2025-11-18 15:30:22 | Projects
📁 DIR  |        --- | 2025-11-17 09:15:10 | Work
📄 FILE | 1.25 MB    | 2025-11-19 14:22:05 | report.pdf
📄 FILE | 512.00 B   | 2025-11-18 11:05:33 | notes.txt
```

**Обработка ошибок**:
- Путь не существует
- Путь не является директорией
- Нет прав доступа на чтение

### 2. change_directory

Навигация по файловой системе (смена текущей рабочей директории).

**Параметры**:
- `path` (str, обязательно): Целевой путь (абсолютный или относительный)

**Поддержка**:
- Абсолютные пути: `/home/user/documents`
- Относительные пути: `../parent`, `./current`
- Специальные пути: `.` (текущая), `..` (родительская)
- Тильда: `~` (домашняя директория)

**Возвращает**:
- Подтверждение смены директории
- Новый текущий путь

**Пример вызова**:
```json
{
  "name": "change_directory",
  "arguments": {
    "path": "~/Documents"
  }
}
```

**Пример ответа**:
```
✅ Текущая директория изменена:
📂 /Users/username/Documents
```

**Важно**: Текущая рабочая директория сохраняется глобально для всех последующих операций с относительными путями.

### 3. read_file

Чтение содержимого текстового файла.

**Параметры**:
- `path` (str, обязательно): Путь к файлу
- `encoding` (str, опционально): Кодировка файла. По умолчанию: `utf-8`

**Поддерживаемые кодировки**:
- `utf-8` (по умолчанию)
- `cp1251` (Windows Cyrillic)
- `latin-1` (ISO-8859-1)
- `ascii`

**Ограничения**:
- Максимальный размер файла для чтения: **10 MB**
- Бинарные файлы не поддерживаются (определяются по расширению)

**Пример вызова**:
```json
{
  "name": "read_file",
  "arguments": {
    "path": "~/Documents/notes.txt",
    "encoding": "utf-8"
  }
}
```

**Пример ответа**:
```
📄 Файл: /Users/username/Documents/notes.txt
Размер: 512.00 B
Кодировка: utf-8
================================================================================
[содержимое файла]
```

**Обработка ошибок**:
- Файл не существует
- Файл является бинарным
- Неверная кодировка (UnicodeDecodeError)
- Файл слишком большой
- Нет прав на чтение

### 4. write_file

Создание нового файла с указанным содержимым.

**Параметры**:
- `path` (str, обязательно): Путь к файлу
- `content` (str, обязательно): Содержимое файла
- `overwrite` (bool, опционально): Разрешить перезапись существующего файла. По умолчанию: `false`
- `encoding` (str, опционально): Кодировка файла. По умолчанию: `utf-8`

**Ограничения**:
- Максимальный размер содержимого: **5 MB**

**Особенности**:
- Автоматическое создание промежуточных директорий (если не существуют)
- Защита от случайной перезаписи (требуется `overwrite=true`)

**Пример вызова**:
```json
{
  "name": "write_file",
  "arguments": {
    "path": "~/Documents/new_file.txt",
    "content": "Hello, World!",
    "overwrite": false
  }
}
```

**Пример ответа**:
```
✅ Файл успешно создан:
📄 Путь: /Users/username/Documents/new_file.txt
Размер: 13.00 B
Кодировка: utf-8
```

**Обработка ошибок**:
- Файл уже существует (без `overwrite=true`)
- Содержимое слишком большое
- Нет прав на запись в директорию

---

### 5. edit_file

Редактирование существующего файла (полная замена содержимого).

**Параметры**:
- `path` (str, обязательно): Путь к файлу
- `new_content` (str, обязательно): Новое содержимое файла
- `create_backup` (bool, опционально): Создать резервную копию перед редактированием. По умолчанию: `true`
- `encoding` (str, опционально): Кодировка файла. По умолчанию: `utf-8`

**Ограничения**:
- Максимальный размер нового содержимого: **5 MB**
- Файл должен существовать (иначе используйте `write_file`)

**Особенности**:
- Автоматическое создание резервной копии с timestamp в имени
- Формат backup: `filename.YYYYMMDD_HHMMSS.backup.ext`
- Попытка восстановления из backup при ошибке

**Пример вызова**:
```json
{
  "name": "edit_file",
  "arguments": {
    "path": "~/Documents/notes.txt",
    "new_content": "Updated content",
    "create_backup": true
  }
}
```

**Пример ответа**:
```
✅ Файл успешно отредактирован:
📄 Путь: /Users/username/Documents/notes.txt
Старый размер: 512.00 B
Новый размер: 15.00 B
Кодировка: utf-8
💾 Резервная копия: /Users/username/Documents/notes.20251120_153045.backup.txt
```

**Обработка ошибок**:
- Файл не существует
- Содержимое слишком большое
- Нет прав на чтение/запись

### 6. get_file_info

Получение детальной метаинформации о файле или директории.

**Параметры**:
- `path` (str, обязательно): Путь к файлу или директории

**Возвращает**:
- Тип объекта (файл, директория, символическая ссылка)
- Имя и полный путь
- Родительская директория
- Размер (для файлов)
- Расширение (для файлов)
- Даты: создания, изменения, последнего доступа
- Права доступа (в формате rwxrwxrwx и octal)
- Доступ текущего пользователя (чтение, запись, выполнение)
- Количество элементов (для директорий)
- Цель (для символических ссылок)

**Пример вызова**:
```json
{
  "name": "get_file_info",
  "arguments": {
    "path": "~/Documents/report.pdf"
  }
}
```

**Пример ответа**:
```
ℹ️ Информация о: /Users/username/Documents/report.pdf
================================================================================
Тип: 📄 Файл
Имя: report.pdf
Родительская директория: /Users/username/Documents
Абсолютный путь: /Users/username/Documents/report.pdf
Размер: 1.25 MB
Расширение: .pdf
Дата создания: 2025-11-18 10:30:15
Дата изменения: 2025-11-19 14:22:05
Дата доступа: 2025-11-20 09:15:33
Права доступа: rw-r--r-- (644)
Доступ (чтение): ✅
Доступ (запись): ✅
Доступ (выполнение): ❌
```

## Безопасность

### Валидация путей

Функция `validate_path()` выполняет следующие проверки:

1. **Расширение тильды** (`~`) до полного пути домашней директории
2. **Разрешение относительных путей** относительно `current_working_directory`
3. **Resolve symlinks** - разрешение символических ссылок и относительных компонентов (`.`, `..`)
4. **Защита системных директорий** - запрет доступа к критическим системным путям

**Защищенные директории** (список можно расширить):
- `/etc` - конфигурационные файлы системы
- `/sys` - системные файлы ядра
- `/proc` - процессы и системная информация
- `/dev` - файлы устройств
- `/boot` - загрузчик системы

**Предотвращение атак**:
- Path traversal (`../../etc/passwd`) - блокируется через `resolve()`
- Доступ к запрещенным директориям - проверка `forbidden_paths`
- Symlink escape - блокируется через `resolve()` и проверку родительских путей

### Ограничения размеров

- **Чтение файлов**: максимум 10 MB
- **Запись/редактирование**: максимум 5 MB

Эти ограничения защищают от:
- Чрезмерного потребления памяти
- DoS атак через большие файлы
- Случайного повреждения больших файлов

### Логирование

Все операции логируются с уровнем INFO:
- Имя инструмента
- Путь к файлу/директории
- Результат операции (успех/ошибка)
- Детали ошибок (с exc_info=True для отладки)

**Пример лога**:
```
2025-11-20 15:30:45 - __main__ - INFO - list_directory: ~/Documents
2025-11-20 15:30:45 - __main__ - INFO - list_directory успешно: 25 элементов
```

## Запуск сервера

### Режим SSE (рекомендуется)

```bash
python mcp_server/filesystem.py
```

Сервер запустится на `http://localhost:8003/sse`

### Режим stdio (для совместимости)

```bash
python mcp_server/filesystem.py --stdio
```

**Внимание**: stdio режим имеет известные проблемы в MCP SDK v1.21.2

## Расширение функциональности

### Добавление новых инструментов

1. Создайте функцию с декоратором `@mcp.tool()`:

```python
@mcp.tool()
async def copy_file(source: str, destination: str) -> str:
    """Копирование файла."""
    # Валидация
    is_valid_src, error_msg_src, src_path = validate_path(source)
    is_valid_dst, error_msg_dst, dst_path = validate_path(destination)

    # Логика копирования
    ...

    return "✅ Файл успешно скопирован"
```

2. Инструмент автоматически появится в списке `list_tools()`

### Настройка безопасности

Расширьте список запрещенных директорий:

```python
forbidden_paths = [
    Path('/etc'),
    Path('/sys'),
    Path('/proc'),
    Path('/dev'),
    Path('/boot'),
    Path('/private'),  # macOS
    Path('C:/Windows'),  # Windows
]
```

### Изменение лимитов

Настройте константы в начале файла:

```python
MAX_FILE_SIZE_READ = 20 * 1024 * 1024  # 20 MB
MAX_FILE_SIZE_WRITE = 10 * 1024 * 1024  # 10 MB
```

## Troubleshooting

### Сервер не запускается

**Проблема**: `Address already in use`

**Решение**: Порт 8003 занят. Измените порт в `filesystem.py`:
```python
mcp.run(transport="sse", port=8004)
```

И в `mcp_client.py`:
```python
"url": "http://localhost:8004/sse"
```

### Ошибки подключения

**Проблема**: `Connection refused`

**Решение**:
1. Убедитесь, что сервер запущен: `ps aux | grep filesystem.py`
2. Проверьте логи сервера
3. Проверьте firewall настройки

### Ошибки прав доступа

**Проблема**: `Permission denied`

**Решение**:
1. Проверьте права на файл/директорию: `ls -la`
2. Убедитесь, что путь не защищен системой
3. Используйте пути в домашней директории пользователя

## Best Practices

1. **Всегда используйте `get_file_info`** перед операциями для проверки существования и прав доступа
2. **Включайте `create_backup=true`** при редактировании важных файлов
3. **Используйте абсолютные пути** для критичных операций
4. **Проверяйте размер файла** через `get_file_info` перед чтением больших файлов
5. **Логируйте операции** на стороне клиента для аудита
6. **Обрабатывайте ошибки** - все инструменты возвращают информативные сообщения об ошибках

## API Reference

### Типы возвращаемых значений

Все инструменты возвращают `str` с:
- ✅ - успешная операция
- ❌ - ошибка
- ℹ️ - информация
- 📂 / 📄 - иконки для визуального разделения

### Форматирование вывода

- Таблицы с выравниванием столбцов
- Разделители (`===`, `---`)
- Размеры в человекочитаемом формате (B, KB, MB, GB)
- Даты в формате `YYYY-MM-DD HH:MM:SS`
- Права доступа в Unix формате (`rwxr-xr-x`)
