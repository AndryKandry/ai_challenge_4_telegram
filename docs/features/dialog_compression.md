# Механизм компрессии истории диалога

## Обзор

Механизм компрессии истории диалога предназначен для оптимизации использования токенов при длительных разговорах с ботом. Система автоматически или по команде пользователя создаёт краткое резюме предыдущих сообщений, заменяя их компактным представлением.

## Назначение

- **Экономия токенов**: Сжатие истории диалога позволяет экономить 30-50% токенов при длительных разговорах
- **Сохранение контекста**: Резюме содержит всю критически важную информацию для продолжения диалога
- **Масштабирование диалогов**: Позволяет вести длительные диалоги без достижения лимитов модели

## Режимы работы

### 1. Ручная компрессия (`/compact`)

Пользователь может вручную запустить компрессию командой `/compact`.

**Поведение:**
- Сжимает **ВСЕ** предыдущие сообщения в одно резюме
- Не сохраняет ни одного исходного сообщения
- Создаёт максимально компактное представление всей истории

**Применение:**
- Когда пользователь хочет полностью очистить историю, сохранив только суть
- Перед началом новой темы разговора
- Для максимальной экономии токенов

**Пример использования:**
```
Пользователь: /compact

Бот: 🗜️ Начинаю компрессию ВСЕЙ истории диалога...

Все предыдущие сообщения будут заменены на краткое резюме.
⏳ Это может занять несколько секунд...

[Через 2-3 секунды]

Бот: 🗜️ Компрессия истории завершена

📊 Статистика:
├─ Сжато сообщений: 45
├─ Сохранено последних: 0
├─ Токенов до: 12,450
├─ Токенов после: 2,890
└─ Экономия: 77%

✅ История диалога оптимизирована для экономии токенов!

Бот: 📋 Резюме вашего диалога:

- Пользователь: разработчик Python, создаёт Telegram-бота
- Задача: интеграция с Yandex GPT API для ИИ-агента
- Выполнено: базовая структура бота, обработка команд, система токенов
- В работе: добавление компрессии истории диалога
- Ключевые решения: асинхронная архитектура, автоматический подсчёт токенов
- Важный контекст: цель - оптимизация расхода токенов
```

### 2. Автоматическая компрессия

Система автоматически запускает компрессию при достижении определённых лимитов.

**Триггеры:**
- **Количество сообщений**: 50 сообщений (по умолчанию)
- **Процент токенов**: 85% от лимита модели (по умолчанию)

**Поведение:**
- Сжимает все сообщения **кроме последних 10**
- Сохраняет недавний контекст для естественного продолжения
- Создаёт резюме из остальных сообщений

**Пример:**
```
[При 50-м сообщении]

Бот: 🗜️ История диалога достигла лимита. Выполняю автоматическую компрессию...
⏳ Секунду...

✅ Автоматическая компрессия выполнена
📊 Сэкономлено: 45% токенов

[Диалог продолжается нормально]
```

## Алгоритм компрессии

### Этап 1: Определение необходимости

```python
def should_compress(history) -> bool:
    # Проверка по количеству сообщений
    if message_count >= 50:
        return True

    # Проверка по процент токенов
    if token_percentage >= 85%:
        return True

    return False
```

### Этап 2: Подготовка данных

Система формирует текстовое представление истории:

```
[Сообщение 1 - Пользователь]
Как создать Telegram бота на Python?

[Сообщение 2 - Ассистент]
Для создания Telegram бота на Python вам понадобится...

[Сообщение 3 - Пользователь]
А как добавить обработку команд?

...
```

### Этап 3: Создание резюме через LLM

Система отправляет историю в Yandex GPT с специальным промптом для создания резюме:

**Параметры запроса:**
- **Temperature**: 0.3 (низкая для стабильности)
- **MaxTokens**: 2000
- **Системный промпт**: "Ты — эксперт по анализу и сжатию информации"

**Структура резюме:**
```
- Пользователь: [краткое описание контекста]
- Задача: [основная цель пользователя]
- Выполнено: [список завершённых действий]
- В работе: [текущие незавершённые задачи]
- Ключевые решения: [важные технические решения]
- Важный контекст: [другая критическая информация]
```

### Этап 4: Замена истории

**Для ручной компрессии (`/compact`):**
```
[Системный промпт]
[COMPRESSED CONTEXT]
Резюме предыдущего диалога:
- Пользователь: разработчик, создаёт Telegram-бота на Python
- Задача: реализовать бота с обработкой команд и интеграцией с Yandex GPT
- Выполнено: базовая структура бота, обработка /start и /help
- В работе: интеграция с Yandex GPT API
- Ключевые решения: использовать python-telegram-bot библиотеку
- Важный контекст: бот должен работать асинхронно
[/COMPRESSED CONTEXT]
[Новые сообщения будут добавляться сюда]
```

**Для автоматической компрессии:**
```
[Системный промпт]
[COMPRESSED CONTEXT]
Резюме предыдущего диалога:
...
[/COMPRESSED CONTEXT]
[Последние 10 сообщений без изменений]
```

## Конфигурация

Настройки компрессии находятся в [config.py](../../config.py):

```python
# Включить механизм компрессии
COMPRESSION_ENABLED = True

# Автоматическая компрессия при достижении лимитов
COMPRESSION_AUTO_COMPRESS = True

# Максимальное количество сообщений до автокомпрессии
COMPRESSION_MAX_MESSAGES = 50

# Максимальный процент использования токенов до автокомпрессии
COMPRESSION_MAX_TOKENS_PERCENT = 0.85  # 85%

# Количество последних сообщений для сохранения (только для автокомпрессии)
COMPRESSION_KEEP_RECENT_MESSAGES = 10

# Целевое соотношение компрессии (20% от исходного размера)
COMPRESSION_RATIO_TARGET = 0.2

# Путь к промпту для компрессии
COMPRESSION_PROMPT_PATH = "prompts/compression_summary.txt"
```

## Метрики и статистика

После каждой компрессии система собирает статистику:

```python
{
    "tokens_before": 12450,      # Токены до компрессии
    "tokens_after": 2890,         # Токены после компрессии
    "savings": 77,                # Процент экономии
    "messages_compressed": 45,    # Количество сжатых сообщений
    "messages_kept": 0,           # Количество сохранённых сообщений (0 для /compact)
}
```

Статистика логируется в формате:
```
INFO: Compression completed: 12450 -> 2890 tokens (77% saved)
```

## Примеры использования

### Пример 1: Ручная компрессия в середине разговора

```
Пользователь: [45 сообщений об обсуждении архитектуры бота]
Пользователь: /compact
Бот: [Выполняет компрессию]
Пользователь: Теперь давай обсудим деплоймент
Бот: [Отвечает, имея доступ к резюме предыдущего контекста]
```

### Пример 2: Автоматическая компрессия

```
Пользователь: [Сообщение #50]
Бот: [Автоматически запускает компрессию]
Бот: ✅ Автоматическая компрессия выполнена
     📊 Сэкономлено: 45% токенов
Бот: [Отвечает на сообщение #50]
```

### Пример 3: Несколько циклов компрессии

```
Диалог: 100 сообщений
↓
Автокомпрессия #1 (при 50 сообщениях)
├─ Сжато: 40 сообщений → резюме
└─ Сохранено: 10 последних

Диалог продолжается: +50 сообщений
↓
Автокомпрессия #2 (при следующих 50 сообщениях)
├─ Сжато: резюме + 40 новых сообщений → обновлённое резюме
└─ Сохранено: 10 последних

Итого: 100 сообщений → резюме + 10 последних сообщений
```

## Ограничения и граничные случаи

### 1. Минимум сообщений

Компрессия требует минимум 2 сообщения в истории:
```python
if history.get_message_count() < 2:
    return "История слишком короткая для компрессии"
```

### 2. Ошибки создания резюме

Если Yandex GPT не может создать резюме:
- Логируется ошибка
- Пользователь получает уведомление
- История остаётся без изменений

### 3. Потеря детализации

Компрессия сохраняет только ключевую информацию. Некоторые детали могут быть потеряны:
- Точные формулировки вопросов
- Промежуточные обсуждения
- Технические детали, признанные неважными LLM

### 4. Зависимость от качества LLM

Качество резюме зависит от способности Yandex GPT выделять ключевую информацию.

## Преимущества

✅ **Экономия токенов**: 30-50% при длительных диалогах
✅ **Автоматизация**: Не требует действий от пользователя
✅ **Гибкость**: Ручная и автоматическая компрессия
✅ **Сохранение контекста**: LLM продолжает понимать суть разговора
✅ **Масштабируемость**: Позволяет вести бесконечно длинные диалоги

## Недостатки

⚠️ **Потеря деталей**: Некоторая информация может быть упущена
⚠️ **Время обработки**: Компрессия занимает 2-5 секунд
⚠️ **Дополнительные вызовы API**: Каждая компрессия = 1 запрос к Yandex GPT
⚠️ **Невосстановимость**: После компрессии исходные сообщения утеряны

## Рекомендации по использованию

1. **Используйте `/compact` перед сменой темы**: Очистите историю перед началом нового обсуждения
2. **Доверьтесь автокомпрессии**: Для большинства случаев автоматическая компрессия работает оптимально
3. **Следите за статистикой**: Обращайте внимание на процент экономии токенов
4. **Не злоупотребляйте ручной компрессией**: Каждая компрессия = дополнительный API-запрос
