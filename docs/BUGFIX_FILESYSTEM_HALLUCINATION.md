# Исправление проблемы галлюцинации write_file

**Дата:** 2025-11-20
**Статус:** Исправлено ✅

## Описание проблемы

Бот писал в Telegram, что файл успешно сохранён (например, `AndryKandry_github_info.txt`), но на самом деле файл не создавался в файловой системе.

### Пример проблемного поведения

```
Пользователь: Сохрани информацию о github пользователе microsoft в файл ~/microsoft_info.txt

Бот: ✅ Файл успешно сохранён: ~/microsoft_info.txt
```

Но при проверке: `ls ~/microsoft_info.txt` → файл не найден.

## Анализ логов

Логи показывали:
```
2025-11-20 13:00:26,973 - providers.deepseek_provider - INFO - MCP Tools доступны: 9 инструментов
2025-11-20 13:00:26,973 - providers.deepseek_provider - INFO - Доступные инструменты: get_user_repositories, get_user_info, get_repository_commits, list_directory, change_directory, read_file, write_file, edit_file, get_file_info
2025-11-20 13:00:35,260 - providers.deepseek_provider - INFO - DeepSeek запросил вызов 2 инструментов
2025-11-20 13:00:35,262 - providers.deepseek_provider - INFO - Вызов MCP tool: get_user_info с аргументами: {'username': 'microsoft'}
2025-11-20 13:00:42,970 - providers.deepseek_provider - INFO - Вызов MCP tool: get_user_repositories с аргументами: {'username': 'microsoft'}
```

### Проблема

DeepSeek **НЕ вызывал write_file инструмент**, хотя:
- ✅ Инструмент write_file был доступен (в списке 9 tools)
- ✅ Инструмент write_file работает корректно (проверено test_filesystem_mcp.py)
- ✅ DeepSeek умеет вызывать другие инструменты (get_user_info, get_user_repositories)
- ❌ DeepSeek "галлюцинировал" - писал что файл сохранён, но не использовал реальный инструмент

## Причина

System промпт не содержал явных инструкций о том, что **ОБЯЗАТЕЛЬНО нужно использовать реальные инструменты** для операций с файлами.

LLM модели (включая DeepSeek) могут:
1. Вызвать реальный инструмент через function calling
2. "Притвориться" что вызвали инструмент (галлюцинация)

Без явных инструкций модель часто выбирает вариант 2, особенно если:
- Запрос пользователя неявный ("сохрани информацию")
- Модель уже получила данные через другие инструменты
- В промпте нет указания "ОБЯЗАТЕЛЬНО используй write_file"

## Решение

Обновлены все три system промпта в `prompts.py`:
- `SYSTEM_PROMPT_DEFAULT` (режим TEXT)
- `SYSTEM_PROMPT_JSON` (режим JSON)
- `SYSTEM_PROMPT_XML` (режим XML)

### Добавлен раздел ИНСТРУМЕНТЫ (MCP Tools)

```python
ИНСТРУМЕНТЫ (MCP Tools):
У тебя есть доступ к внешним инструментам (GitHub, Filesystem и др.).
КРИТИЧЕСКИ ВАЖНО: Когда пользователь просит:
- "Сохрани в файл" / "Создай файл" / "Запиши в файл" → ОБЯЗАТЕЛЬНО используй инструмент write_file
- "Прочитай файл" → используй инструмент read_file
- "Покажи содержимое папки" → используй инструмент list_directory
- "Информация о GitHub пользователе" → используй инструмент get_user_info
НЕ делай вид, что выполнил действие - ИСПОЛЬЗУЙ РЕАЛЬНЫЙ ИНСТРУМЕНТ через function calling!
Если инструмент вернул результат, опиши его пользователю. Если инструмент не вызван - НЕ пиши "файл сохранён".
```

### Ключевые фразы для DeepSeek

1. **"КРИТИЧЕСКИ ВАЖНО"** - усиливает важность инструкции
2. **"ОБЯЗАТЕЛЬНО используй инструмент"** - явное требование
3. **"НЕ делай вид"** - запрещает галлюцинацию
4. **"ИСПОЛЬЗУЙ РЕАЛЬНЫЙ ИНСТРУМЕНТ"** - подчёркивает необходимость function calling
5. **"Если инструмент не вызван - НЕ пиши 'файл сохранён'"** - прямой запрет на ложные утверждения
