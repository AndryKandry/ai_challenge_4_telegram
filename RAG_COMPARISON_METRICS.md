# Метрики режима сравнения RAG

## Обзор

Документ описывает все метрики, собираемые в режиме сравнения RAG, методы их расчета и интерпретацию результатов.

## Основные метрики

### 1. Токены (Token Count)

**Описание:** Приблизительное количество токенов в сгенерированном ответе.

**Метод расчета:**
```python
token_count = int(len(response_text.split()) * 1.3)
```

**Интерпретация:**
- **Низкое значение (менее 100):** Краткий, возможно неполный ответ
- **Среднее значение (100-500):** Стандартный детальный ответ
- **Высокое значение (более 500):** Очень подробный, возможно избыточный ответ

**Факторы влияния:**
- Количество и качество контекста
- Сложность запроса пользователя
- Настройки temperature модели

### 2. Время генерации (Generation Time)

**Описание:** Точное время в секундах, затраченное на генерацию ответа LLM.

**Метод измерения:**
```python
start_time = time.time()
response = await llm.generate(context)
generation_time = time.time() - start_time
```

**Интерпретация:**
- **Быстрое (< 1 сек):** Оптимальная производительность
- **Среднее (1-3 сек):** Нормальная производительность
- **Медленное (> 3 сек):** Возможны проблемы с API или сложный контекст

### 3. Количество использованных документов (Documents Used)

**Описание:** Количество документов, переданных в контекст LLM.

**Значения по умолчанию:**
- Вариант A (без reranking): K = 5 случайных документов
- Вариант B (с reranking): K = 5 топовых документов

**Интерпретация:**
- Фиксированное значение позволяет сравнивать качество контекста
- Может быть адаптировано под конкретные сценарии

### 4. Размер контекста (Context Size)

**Описание:** Общая длина строкового представления контекста в символах.

**Метод расчета:**
```python
context_size = len(context_string)
```

**Интерпретация:**
- **Малый (< 1000 символов):** Может не содержать достаточно информации
- **Средний (1000-5000 символов):** Оптимальный баланс
- **Большой (> 5000 символов):** Риск превышения лимитов токенов

### 5. Оценка релевантности документов (Relevance Scores)

**Описание:** Similiraty score для каждого документа в контексте (диапазон 0.00-1.00).

**Источники оценок:**
- **Вариант A:** Исходные scores из векторного поиска (cosine similarity)
- **Вариант B:** Обновленные scores после reranking

**Формат отображения:**
```
1. document_name.pdf - релевантность: 0.85
2. guide_text.txt - релевантность: 0.73
3. manual_page.md - релевантность: 0.67
```

### 6. Средняя релевантность (Average Relevance)

**Описание:** Среднее арифметическое всех relevance scores в контексте.

**Метод расчета:**
```python
avg_relevance = sum(doc.relevance for doc in documents) / len(documents)
```

**Интерпретация:**
- **Высокая (> 0.8):** Очень релевантный контекст
- **Средняя (0.5-0.8):** Умеренно релевантный контекст
- **Низкая (< 0.5):** Слабо релевантный контекст

### 7. Полнота ответа (Completeness Score)

**Описание:** Эвристическая оценка полноты и качества ответа.

**Метод расчета:**
```python
def calculate_completeness_score(response_text: str) -> float:
    score = 0.0
    
    # Количество предложений (base score)
    sentences = len(response_text.split('.'))
    score += sentences * 1.0
    
    # Наличие числовых данных
    numeric_facts = len(re.findall(r'\d+', response_text))
    score += numeric_facts * 2.0
    
    # Наличие структурированных элементов
    if '•' in response_text or '1.' in response_text:
        score += 5.0
    
    # Наличие цитат или ссылок
    if '"' in response_text or 'http' in response_text:
        score += 3.0
    
    return score
```

**Интерпретация:**
- **Низкая (< 10):** Максимально краткий ответ
- **Средняя (10-25):** Стандартный информативный ответ
- **Высокая (> 25):** Очень подробный ответ с примерами

## Сравнительные метрики

### 1. Разница в токенах

**Описание:** Абсолютная и процентная разница между вариантами.

**Метод расчета:**
```python
token_diff = variant_b.token_count - variant_a.token_count
token_diff_percent = (token_diff / variant_a.token_count) * 100
```

**Интерпретация:**
- **Положительная разница:** Вариант B содержит больше информации
- **Отрицательная разница:** Вариант A более лаконичный
- **Нулевая разница:** Оба варианта одинаковы по объему

### 2. Разница во времени генерации

**Описание:** Разница во времени между вариантами.

**Интерпретация:**
- Может указывать на сложность контекста
- Помогает оценить эффективность выбора документов

### 3. Разница в средней релевантности

**Описание:** Ключевая метрика эффективности reranking.

**Метод расчета:**
```python
relevance_diff = variant_b.avg_relevance - variant_a.avg_relevance
relevance_diff_percent = (relevance_diff / variant_a.avg_relevance) * 100
```

**Интерпретация:**
- **Положительная (> 0.1):** Reranking значительно улучшил контекст
- **Небольшая (0.0-0.1):** Незначительное улучшение
- **Отрицательная (< 0):** Reranking ухудшил контекст

### 4. Эффективность reranking

**Описание:** Качественная оценка влияния reranking.

**Критерии классификации:**
```python
def evaluate_reranking_effectiveness(relevance_diff: float) -> str:
    if relevance_diff > 0.2:
        return "улучшение"
    elif relevance_diff < -0.1:
        return "ухудшение"
    else:
        return "нейтрально"
```

### Пороговые значения

Рекомендуемые пороги для оценки системы:

| Метрика | Плохо | Удовлетворительно | Хорошо | Отлично |
|----------|--------|------------------|---------|---------|
| Средняя релевантность A | < 0.3 | 0.3-0.5 | 0.5-0.7 | > 0.7 |
| Средняя релевантность B | < 0.4 | 0.4-0.6 | 0.6-0.8 | > 0.8 |
| Улучшение от reranking | < 0% | 0-10% | 10-20% | > 20% |
| Время генерации | > 5 сек | 3-5 сек | 1-3 сек | < 1 сек |

### Тренды и паттерны

#### Типичные паттерны:

1. **Высокая базовая релевантность (A > 0.6):**
   - Reranking дает минимальные улучшения
   - Система поиска уже работает хорошо

2. **Низкая базовая релевантность (A < 0.3):**
   - Потенциал для значительных улучшений
   - Возможны проблемы с индексом

3. **Большая разница в объеме ответов:**
   - Может указывать на различия в контексте
   - Требуется дополнительный анализ

4. **Превышение времени генерации:**
   - Аномалия, требующая внимания
   - Возможны проблемы с API

## Рекомендации по оптимизации

### На основе метрик релевантности:

1. **Если средняя релевантность < 0.4:**
   - Проверить качество индексации документов
   - Улучшить чанкинг (размер и перекрытие)
   - Рассмотреть другие модели эмбеддингов

2. **Если улучшение от reranking < 5%:**
   - Оптимизировать алгоритм ранжирования
   - Увеличить количество документов для анализа
   - Рассмотреть machine learning подходы

3. **Если время генерации > 3 сек:**
   - Оптимизировать размер контекста
   - Использовать более быстрые модели
   - Ввести кэширование результатов

### На основе метрик ответов:

1. **Низкая полнота ответа (< 10):**
   - Увеличить количество контекстных документов
   - Улучшить промпты для генерации
   - Добавить постобработку ответов

2. **Большая разница в токенах (> 50%):**
   - Проанализировать контексты обоих вариантов
   - Проверить равномерность распределения документов

## Заключение

Метрики режима сравнения RAG предоставляют комплексную оценку эффективности системы. Регулярный анализ этих метрик позволяет:

- Выявлять проблемы в поиске и ранжировании
- Оптимизировать параметры системы
- Отслеживать improvements над временем
- Обосновывать технические решения

Ключевая метрика - **улучшение средней релевантности** - прямое отражение эффективности reranking алгоритма. Комплексный подход с учетом всех метрик обеспечивает полноценную оценку системы RAG.
