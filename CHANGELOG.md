# Changelog

## [1.2.2] - 2025-11-20

### 🐛 Исправления

#### 1. Ошибка "unable to open database file" при запуске Telegram MCP сервера
- **Проблема:** При запуске MCP сервера возникала ошибка "unable to open database file" из-за отсутствия директории `data`
- **Решение:** Добавлено автоматическое создание директории для session файлов Pyrogram
- **Файлы:** `mcp_server/telegram_assistant.py:72-75`

#### 2. Автоматические сводки не выполнялись по расписанию
- **Проблема:** Задачи добавлялись в планировщик, но не выполнялись - отсутствовало логирование событий выполнения
- **Решение:**
  - Добавлены event listeners для мониторинга выполнения задач (executed, error, missed)
  - Добавлено детальное логирование при добавлении задач и их выполнении
  - Добавлена диагностическая информация о состоянии задач
- **Файлы:**
  - `scheduler/manager.py:63-67, 75-85, 216-221` - event listeners
  - `scheduler/tasks.py:34-35, 47` - улучшенное логирование

#### 3. Блокировка при создании первоначальной сводки
- **Проблема:** Pyrogram требует интерактивную авторизацию при первом запуске, что блокирует работу MCP сервера
- **Решение:** Создан скрипт `setup_telegram_session.py` для предварительной авторизации
- **Инструкция:** Перед первым использованием запустить `python setup_telegram_session.py`

### 📝 Улучшения

- Добавлены эмодзи в логи для лучшей читаемости (✅, ❌, ⚠️, 🚀)
- Улучшена диагностика состояния задач в планировщике
- Создан скрипт для упрощения первоначальной настройки Telegram клиента

## [1.2.1] - 2025-11-20

### 🐛 Исправления

#### 1. Первоначальная сводка не создавалась
- **Проблема:** LLM задавал вопросы вместо создания сводки
- **Решение:** Улучшены системные промпты - более директивные инструкции
- **Файлы:** `scheduler/tasks.py` (строки 193-202, 466-476)

- **Проблема:** Задачи не выполнялись через заданный интервал
- **Решение:**
  - Исправлено установка `last_run_at` при создании (было `now`, стало `None`)
  - Улучшена логика восстановления задач после перезапуска
  - Исправлено обновление `next_run_at` после выполнения задачи
- **Файлы:** `scheduler/manager.py` (строки 131-138, 373-413), `scheduler/tasks.py` (строки 129-146)

### 📝 Документация

- Создан `docs/BUGFIXES_2025-11-20.md` с подробным описанием исправлений и тестами

## [1.1.0] - 2025-11-19

### 🐛 Исправления

#### 1. DeepSeek Provider - множественные MCP клиенты
- **Проблема:** DeepSeek не мог вызывать Telegram Assistant MCP tools
- **Решение:** Добавлена поддержка нескольких MCP клиентов одновременно
- **Файлы:** `providers/deepseek_provider.py`, `bot.py`

#### 2. Расписание ассистентов
- **Проблема:** Ассистенты не запускались по расписанию, `next_run_at` показывал `-`
- **Решение:** Исправлена логика вычисления времени первого запуска
- **Файлы:** `scheduler/manager.py`

#### 3. Удаление ассистентов
- **Проблема:** Не было команд для удаления ассистентов из БД
- **Решение:** Добавлены команды `/delete_assistant` и `/delete_all_assistants`
- **Файлы:** `scheduler/manager.py`, `storage/database.py`, `bot.py`

### ✨ Новые команды

- `/delete_assistant <chat_name>` - Удалить ассистента
- `/delete_all_assistants confirm` - Удалить все ассистенты

### 📝 Документация

- Создан `docs/BUGFIXES_2025-11-19.md` с подробным описанием всех исправлений

## [1.0.0] - 2025-11-19

### ✨ Основной функционал

#### Первоначальная сводка при создании ассистента
- При создании ассистента автоматически создаётся сводка по последним 100 сообщениям
- Подробности в `docs/INITIAL_SUMMARY_FEATURE.md`

- Полная интеграция с Telegram Bot
- Поддержка MCP сервера для доступа к Telegram API
- APScheduler для планирования задач
- SQLite база данных для хранения ассистентов

### 📋 Команды

- `/telegram_assistant <chat_id>` - Создать ассистента
- `/list_assistants` - Список всех ассистентов
- `/stop_assistant <chat_name>` - Остановить ассистента
- `/stop_all_assistants confirm` - Остановить все
